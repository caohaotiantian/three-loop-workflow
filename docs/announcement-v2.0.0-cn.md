## 你会得到什么

| | v1.14.0 | v2.0.0 |
|---|---|---|
| `SKILL.md`(每次都加载) | 2,915 词 | **1,317 词** |
| 全部散文(仅 Markdown) | 21,802 词 | **6,042 词** |
| 文件数(含脚本) | 20 | **8** |
| 每个任务提交的文档 | 2 | **0** |

纪律本身活下来了,交付方式没有。

**Plan → Build → Close** 取代 L1 → L2 → L3 → F。L1 与 L2 本来就是一份计划被切成两半;合并之后,一整个评审循环、slug 协议、回滚协议都随之消失。计划现在是受 gitignore 的 `.agent/<task>/plan.md`,每个任务一个目录,而不是两份提交进仓库的文档。旧的每任务归档已经涨到 43,822 词,而真正交付的产品只有 27,896 词,并且从来没有人类读过它。

**Deep / Standard / Direct** 取代 Full / Light / None,由两个问题决定:*如果这件事做错了,会波及多少?* 以及 *撤销它有多难?* 深度档现在是一份**清单,不是感觉** —— 没有任何一条命中,Standard 就是正确答案。一个高风险的局部,不再会把整个变更升档。

**门禁永远先于评审者。** 你项目自己的 typecheck、lint、build、test 会在派出任何 subagent 之前运行。v1 只在一处括号里提过一次。

**Deep 档两名评审者,Standard 档一名 —— 实测,不是猜。** 在 4 份真实设计文档、每份 3 名独立评审者的条件下:1 名评审者找到 56.5% 的缺陷,2 名找到 85.5%,第 3 名只再增加约 14%。评审者漏掉的是**不同的**东西 —— 只有 19% 的缺陷被三个人同时发现。

**发现会先分诊,再计数。** 同一次测量显示,被判为 *blocking* 的发现只有 50–70% 经得起对抗式复核,其余等级的只有 30–46%。收敛判定现在基于已确认的发现,因此一条并不存在的缺陷,不会再白白消耗一轮修复,也不会把轮次上限假性耗尽。

**有两样东西因为通不过自己的测试而被删除。** 一致性门禁在核心终止规则被替换成语义完全相反的版本之后,依然返回 `OK`、退出码 0。行为测试套件在屏蔽 skill 的条件下跑出 6/6 —— 与加载 skill 那一臂完全一致,区分度 0%,却连续 16 个版本亮着绿灯、不测量任何东西。替代方案会跑两条臂,并把两臂都答对的 fixture 判为 **INVALID** 而不是绿灯。

## 如何升级

**替换整个文件夹,不要往里复制。** v1 与 v2 只有两个文件名相同 —— `SKILL.md` 和 `references/platforms.md`。把 v2 覆盖到 v1 上,只会覆盖这两个,**另外 18 个 v1 文件**会原地残留(`loop-1-design.md`、`l3-phase.js`、`check-consistency.sh` 等等)。没有任何东西会路由到它们,但它们仍然躺在目录里,等着某个 agent 去发现并阅读。

```bash
rm -rf ~/.claude/skills/three-loop-workflow
cp -r three-loop-workflow ~/.claude/skills/

# 或者
rsync -a --delete three-loop-workflow/ ~/.claude/skills/three-loop-workflow/
```

然后:

- **把 `.agent/` 加进 `.gitignore`。** 计划现在放在那里。
- **删掉 hook 配置。** v1 随包发布过一个可选的提交信息 lint:`validate-commit-msg.sh`,v2 不再提供。
  如果你的 `settings.json` 调用过它,请删除那个条目 —— 指向不存在命令的 hook 会在每次提交时报错。
- **你的 `CLAUDE.md` anchor map 不用改。** 还是那五个角色。如果你也维护 `AGENTS.md`,v2 会一并读取;
  两个都在时两个都读。
- **`docs/design/` 与 `docs/implementation/` 不再产出。** 已有归档留着或删掉都行,没有任何东西读它们。
- **更新引用了旧术语的项目文档。** L1/L2/L3/F → Plan/Build/Close;Full/Light/None →
  Deep/Standard/Direct;severe/general → blocking/non-blocking。

继续留在 v1 是可行的,只是它不再演进 —— `git checkout v1.14.0`,或从 v1.14.0 release 下载 `.skill`。
它不会再有任何改动。

## 采用之前你应该知道的两件事

**v2 不再机械强制任何东西。** 里面的每一条规则,都是 agent 可以拒绝的请求。在开发过程中,v2 曾带有 `require-plan.sh` —— 一个在没有计划时拦截对契约文件编辑的 hook,它让「没有计划就不能改契约文件」成为一条真正的**保证**。这个 hook 在发布前被刻意移除了,于是那条保证如今只是一条**约定**。v1 同样没有这个 hook;它唯一发布过的 hook 是一个可选的提交信息 lint。这一点写在这里而不是藏起来,因为这是 v2 唯一一处比它曾经短暂具备的状态更弱的地方。

**这套纪律的大部分,与 Opus 5 自身的判断是重复的。** 这一点我们也测了。7 个行为 fixture 里,有 6 个被一个**被禁止阅读 skill** 的 agent 正确回答。只有一个产生了区分度 —— 就是那条反直觉的规则:一个高风险的局部不会把整个变更升档。这个 skill 的价值集中在**具体而出人意料**的规则上,而不在那些复述常识工程实践的规则上。我们主动公布这一点,是因为它就摆在本仓库的 `tests/expected.json` 里,你迟早会看到。
